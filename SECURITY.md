# Security Policy

## Our Commitment to Security

The International Community School of Abidjan (ICSA) is committed to maintaining the security and privacy of our educational technology platforms and protecting our school community's information.

## Supported Versions

We actively maintain security for the following:

| Repository Type | Supported | Notes |
| --- | --- | --- |
| Current Educational Projects | ✅ | Actively monitored and updated |
| Student Assignment Repositories | ✅ | Reviewed regularly during academic terms |
| Administrative Tools | ✅ | High priority security monitoring |
| Archived/Legacy Projects | ⚠️ | Limited support, case-by-case basis |

## What to Report

Please report security vulnerabilities for:

### High Priority
- **Student Data Exposure**: Any unauthorized access to student information
- **Authentication Issues**: Problems with login systems or access controls
- **Administrative System Vulnerabilities**: Issues affecting school management tools
- **Malicious Code**: Suspected malware or harmful code in repositories

### Medium Priority
- **Educational Tool Vulnerabilities**: Security issues in learning applications
- **Data Integrity Issues**: Problems that could corrupt educational data
- **Dependency Vulnerabilities**: Known security issues in third-party libraries

### Educational Context
- **Inappropriate Content**: Non-educational or harmful content in student repositories
- **Privacy Concerns**: Potential exposure of personal information
- **Academic Integrity**: Suspected sharing of assignment solutions inappropriately

## How to Report a Vulnerability

### For Immediate Threats
**DO NOT** create a public issue for security vulnerabilities.

Contact the ICSA administration immediately through:
1. **Email**: Send details to the school's IT administration (contact through official ICSA channels)
2. **Phone**: Call the school's main number during business hours
3. **In Person**: Visit the school's administrative office

### For Non-Critical Issues
1. Create a private issue using GitHub's security advisory feature
2. Email the repository maintainers with details
3. Use the school's internal reporting systems

### Information to Include
Please provide as much of the following information as possible:
- **Description**: Clear explanation of the vulnerability
- **Location**: Which repository, file, or system is affected
- **Impact**: Potential consequences of the vulnerability
- **Steps to Reproduce**: How to demonstrate the issue
- **Suggested Fix**: If you have ideas for resolution
- **Your Contact Information**: How we can reach you for follow-up

## Our Response Process

### Timeline
- **Initial Response**: Within 24 hours during school days
- **Assessment**: Within 72 hours for evaluation and triage
- **Resolution**: Timeline depends on severity and complexity
- **Follow-up**: Regular updates until resolution

### What to Expect
1. **Acknowledgment**: We'll confirm receipt of your report
2. **Assessment**: We'll evaluate the vulnerability and its impact
3. **Resolution**: We'll work to fix the issue appropriately
4. **Communication**: We'll keep you informed of progress
5. **Recognition**: We'll acknowledge your contribution (if desired)

## Security Best Practices for Contributors

### For Students
- **Never commit sensitive information** (passwords, API keys, personal data)
- **Use strong, unique passwords** for your GitHub account
- **Enable two-factor authentication** on your GitHub account
- **Be cautious with public repositories** - don't share personal information
- **Report suspicious activity** you notice in school repositories

### For Educators
- **Review student code** for potential security issues before approval
- **Use private repositories** for sensitive educational content
- **Regularly update dependencies** in educational tools
- **Follow data privacy guidelines** when handling student information
- **Educate students** about secure coding practices

### For Everyone
- **Keep software updated**: Use current versions of Git, browsers, and development tools
- **Verify repository authenticity**: Ensure you're working with official ICSA repositories
- **Use secure networks**: Avoid public Wi-Fi for sensitive school work
- **Follow school policies**: Adhere to ICSA's technology usage guidelines

## Scope

This security policy applies to:
- All repositories in the ICS-Abidjan GitHub organization
- Related school technology platforms and tools
- Student, educator, and community interactions within our digital spaces
- Educational data and systems accessed through these platforms

## Data Protection

### Student Privacy
- Student work and personal information are protected according to educational privacy laws
- Access to student repositories is limited to authorized educators and the students themselves
- Personal information should never be committed to version control

### Educational Records
- Academic work and assessments are treated as confidential educational records
- Proper access controls are maintained for grade books and assessment tools
- Data retention follows school policies and applicable regulations

## Contact Information

For security-related questions or concerns:

- **Emergency Security Issues**: Contact ICSA administration immediately
- **General Security Questions**: Use repository discussions or issues (for non-sensitive topics)
- **School IT Support**: Through official ICSA channels
- **Website**: [www.icsabidjan.org](https://www.icsabidjan.org/)

## Recognition

We appreciate security researchers and community members who help keep our educational environment safe. Contributors who responsibly disclose security issues will be acknowledged (with their permission) in our security acknowledgments.

Thank you for helping us maintain a secure learning environment for the ICSA community!
